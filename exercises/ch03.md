# 第3章：CLI 工作流

对应书稿 3.8，共 5 题。题干为摘要；按书中原顺序编号。核查日期：2026-09-18。共同前提与验证记录见 [练习说明](README.md)。

## 3.8-1 命名与状态查看

前提：进入测试 Profile 的交互会话。

参考步骤：依次输入 `/title demo-cli-workflow`、`/status`、`/model`、`/tools list`、`/history`，记录会话标题、当前模型、工具和历史。书中的 `/工具 list` 应勘误为 `/tools list`。

验收：能区分会话内斜杠命令与系统终端的 hermes 命令；标题可在会话列表查到。

排查与边界：/model 可能进入选择界面，不要为做题误改生产模型。

## 3.8-2 多行代码审查

前提：使用 [ch03 材料](../examples/ch03-code-review-auth/README.md)，认证缺陷是刻意保留的练习点。

参考步骤：将提示分成四行：目标=审查 auth-change.diff；范围=仅认证样例；约束=只读，不修复；输出=文件行号、原因、验证建议。一次性粘贴完整提示，观察 diff/读取/测试的实际工具轨迹，并与 expected-findings.md 对照。

验收：指出改密后旧会话未失效的风险，并提供代码证据；记录工具结果，不只引用模型自评。

排查与边界：测试通过不表示所有安全属性正确；不得为优化仓库擅自消除练习用缺陷。

## 3.8-3 压缩与继续

前提：准备一段含目标、决定、未完事项的会话。

参考步骤：记下三项状态，输入 `/compress`，正常退出，再在相同 Profile 下运行 `hermes -p book-lab -c`。请其概括目标和未完事项，与压缩前记录对照。

验收：恢复的是预期会话，关键决定保留；记录无法恢复的细节。

排查与边界：不要换 Profile 后误把新会话当旧会话；压缩不是逐字无损存档。

## 3.8-4 SOUL 风格对比

前提：仅使用专用 Profile，备份已有 SOUL.md。

参考步骤：在 Profile 的 SOUL.md 中合并“回答先给结论；用简短中文；明确区分事实与建议”。分别在修改前后开启新会话，问同一问题“解释一次代码审查的验收标准”。

验收：比较顺序、长度、语气、事实一致性；样本和模型保持一致。测试后恢复原文件或保留已确认风格。

排查与边界：人格文件不是提升工具权限的办法，也不保证模型严格逐字服从。

## 3.8-5 一次性输出

前提：真实终端 TTY 下测试，模型可用。

参考步骤：运行 `hermes -z "只回复：测试完成"`，再 `hermes chat --oneshot -q "只回复：测试完成"`。分别记录 stdout、stderr 和退出行为。

验收：两条都应完成后退出；-z 用于简洁最终输出。不得仅凭 `chat -q` 就保证退出。

排查与边界：当前 -q 只给初始问题，TTY 中可继续交互；自动化应显式 --oneshot。

依据：[本章官方参考](https://hermes-agent.nousresearch.com/docs/reference/cli-commands)。具体命令以已安装版本帮助为准；题干需修改处另见 [书稿勘误](../docs/book-errata-2026-09-18.md)。
