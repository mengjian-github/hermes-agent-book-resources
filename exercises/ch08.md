# 第8章：定时任务

对应书稿 8.7，共 5 题。题干为摘要；按书中原顺序编号。核查日期：2026-09-18。共同前提与验证记录见 [练习说明](README.md)。

## 8.7-1 一次性提醒与手动触发

前提：测试 Profile 已配模型，Gateway 正在运行。

参考步骤：`hermes -p book-lab cron create "in 30m" "提醒我检查练习结果" --name book-once --deliver local`，list 记 ID，再 `hermes -p book-lab cron run <ID>`；等待 tick 和实际输出，检查任务是否已完成。

验收：一次性任务手动执行后不可假定30分钟时仍再执行；若还需要定时提醒，应另外创建。完成后按 ID remove。

排查与边界：run 返回只表示请求，不证明输出已生成。

## 8.7-2 间隔与日历调度

前提：使用[日报流程](../examples/ch08-daily-tech-brief/README.md)，首次用 local 投递。

参考步骤：分别创建 `every 1d` 与 `0 9 * * *` 的测试任务，prompt 为输出当前运行时间；比较 list 的 next run 与机器/Gateway 时区。

验收：解释间隔计时与每天09:00的区别，记录具体 next run；实验后移除多余任务。

排查与边界：不要假定表达式自动使用读者所在时区，也不要凭任务名称判断调度。

## 8.7-3 脚本 JSON 输入

前提：脚本及数据均须装入目标 Profile scripts 范围。

参考步骤：先运行 tech_daily.py，再用 install.py --hermes-home 指向真实 Profile；按[完整注册命令](../examples/ch08-daily-tech-brief/README.md)创建、run、检查产物。

验收：stdout 合法 JSON；摘要使用两项 fixture 并标“离线样例”。安装后从无关目录启动仍可读数据。

排查与边界：只复制脚本不复制数据会失败；保存 YAML 本身不会注册 Cron。

## 8.7-4 静默机制

前提：先用无风险测试任务，避免向群发送多余消息。

参考步骤：A：--deliver local，成功后检查本地产物；B：配置测试投递目标，要求成功时最终回答包含 `[SILENT]`，检查成功结果保留但不投递。两项分开记录。

验收：标记作用于最终响应，不是任务名称前缀；不承诺错误通知也静默。

排查与边界：不能以未收到消息直接判定静默成功，先排除任务失败与投递配置错误。

## 8.7-5 Gateway 和执行状态

前提：使用与任务一致的 Profile。

参考步骤：`hermes -p book-lab gateway status`、`hermes -p book-lab cron status`、`hermes -p book-lab cron list`，核对任务 ID、状态、next run；对照日志和 cron/output 的时间戳。

验收：证据链包括调度器运行、任务被执行、结果已保存；服务管理器状态不适用时结合前台进程/日志。

排查与边界：检查错 Profile 或只看 next run 都不足以证明已执行。

依据：[本章官方参考](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)。具体命令以已安装版本帮助为准；题干需修改处另见 [书稿勘误](../docs/book-errata-2026-09-18.md)。
