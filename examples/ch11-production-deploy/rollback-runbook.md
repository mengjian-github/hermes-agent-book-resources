# 备份与回滚演练

1. 记录当前 Hermes 版本/提交、Python 版本、Profile 路径、服务启动命令和最近一次成功验收。
2. 暂停专用 Profile 的调度并停止其 Gateway，确认没有进行中的任务；备份该 Profile 的配置、受保护凭据、状态库、记忆、Skills、Cron 和必要输出。SQLite 使用一致性备份或停机副本，不复制正在写入的孤立数据库文件。
3. 将备份放在限制访问的独立位置，记录清单与校验值；密钥不进入 Git。本步骤由操作者执行，不在示例脚本中自动覆盖目录。
4. 在新测试目录恢复副本，先用本地投递和测试 Bot 验证，避免重复运行生产任务。确认模型、两卷读写边界、文件输出和状态数据后，再恢复原服务。
5. 若升级失败，停止新版，恢复已记录的旧版运行环境和对应数据副本；数据库迁移可能不可逆，不能只降级程序。保留失败现场以便分析。
6. 记录恢复耗时、丢失数据范围、验证结果、操作者和回退点。仅存在备份文件不等于恢复演练通过。
