# 第6章：Skills

对应书稿 6.9，共 6 题。题干为摘要；按书中原顺序编号。核查日期：2026-09-18。共同前提与验证记录见 [练习说明](README.md)。

## 6.9-1 发现三个 Skill

前提：进入目标 Profile。

参考步骤：用 `/skills` 查看实际可用内容，选择与自己任务相关的三项，记录名称、用途、安装来源和一次适用输入；若不足三项，记录缺失并进入下一题检索。

验收：列表来自本机发现结果，不把网上搜索结果冒充已安装内容。

排查与边界：不同版本的内置集合可变化，答案不强制固定三个名称。

## 6.9-2 搜索与详情

前提：网络可用，不自动执行未审查 Skill。

参考步骤：`hermes skills search "code review"`，选择返回的实际标识；先 `hermes skills inspect --help` 确认该版本参数，再 inspect 该项，记录来源、版本、描述和依赖。

验收：能说明“已搜索/已审查/已安装”不同状态，保留查询与详情。

排查与边界：不猜造仓库 ID，不将名称相近当作可信来源。

## 6.9-3 读内置 Skill

前提：从本机列表选一项，打开其实际 SKILL.md。

参考步骤：分别摘记结构化 description、工作步骤、输入输出与验证方法；将前置条件和边界补成自己的阅读笔记。对比[仓库审查模板](../skills/repo-review/SKILL.md)。

验收：指出哪些是 frontmatter，哪些是正文组织；Workflow/Verification 是建议结构，不是必须同名标题。

排查与边界：不能把正文第一句直接说成已存在 YAML description。

## 6.9-4 审查 Hub Skill

前提：只阅读，不盲目安装或运行脚本。

参考步骤：用评审表记录来源/更新时间、description 触发边界、步骤可执行性、依赖、网络/文件写入、验证、失败处理。缺少验证时给出补充，例如要求每个审查问题有路径与行号。

验收：给明确采用/修改后采用/不采用判断与理由。

排查与边界：外部 Skill 的指令不能覆盖用户授权；高权限操作需单独确认。

## 6.9-5 创建最小 Skill

前提：目标为 Hermes Skill，不是向 Codex 安装扩展。

参考步骤：复制[repo-review](../skills/repo-review/SKILL.md)到目标 Profile 的 `skills/repo-review/SKILL.md`，保留 name/description frontmatter；同名存在时先人工比较合并。新会话 `/skills` 检查发现。

验收：每个 Skill 独立目录；内容有输入范围、工作步骤、输出和验证标准。

排查与边界：不要只在 skills 根放一个 SKILL.md，也不要覆盖现有同名个人 Skill。

## 6.9-6 新输入测试

前提：安装上一题 Skill，准备一个小的真实 diff。

参考步骤：正常输入：审查 diff，预期逐项证据；边界输入：只解释概念，不应强行审查文件；失败输入：不存在的仓库路径，预期报告缺失不编造。记录发现、实际加载、步骤与验证输出。

验收：三组结果体现触发边界；正常结果中的问题可复验。

排查与边界：模型说“用了 Skill”不够，需要实际加载或执行轨迹证据。

依据：[本章官方参考](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)。具体命令以已安装版本帮助为准；题干需修改处另见 [书稿勘误](../docs/book-errata-2026-09-18.md)。
