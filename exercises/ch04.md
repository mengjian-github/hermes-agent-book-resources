# 第4章：Profile 与配置

对应书稿 4.8，共 5 题。题干为摘要；按书中原顺序编号。核查日期：2026-09-18。共同前提与验证记录见 [练习说明](README.md)。

## 4.8-1 确认生效配置

前提：不要输出密钥。

参考步骤：用 `hermes profile list` 查看 Profile，`hermes profile show book-lab` 确认路径；进入该 Profile 后 `/status`、`/model` 查看实际模型。记录 config.yaml 路径与当前启动目录。

验收：实际状态与准备使用的 Profile 一致；模型正式字段是 model.default/provider，不是 model.name。

排查与边界：查看另一个目录下的 config.yaml 不能证明它已被加载。

## 4.8-2 创建 work

前提：work 尚不存在；已有则使用或选新的测试名。

参考步骤：依次 `hermes profile create work`、`hermes -p work model`、`hermes -p work doctor`，再发一个一次性测试问题。

验收：work 可独立调用模型，记录诊断未通过项，不将默认 Profile 的凭据状态当作 work 的状态。

排查与边界：首次模型未配置并非练习失败，按向导完成后复验。

## 4.8-3 密钥不进 YAML

前提：使用模型向导或目标 Profile 的 .env。

参考步骤：查明选择的提供商所需变量名，仅在受限凭据文件中填写；打开 config.yaml 检查只含 provider、default 等非敏感信息。提交前检查 git diff 和暂存区。

验收：演示只展示变量名及“已配置”，不得展示值；仓库不包含真实 .env。

排查与边界：不能把 .env.example 中的占位字符串视为可用 Key；泄露后应撤销重发。

## 4.8-4 Docker 实际验证

前提：Docker 已安装并运行；参考[部署例](../examples/ch11-production-deploy/README.md)。

参考步骤：将测试 Profile 的 terminal.backend 改为 docker，doctor 后启动会话，让终端工具显示当前路径、读取挂载测试文件并写输出卷。记录宿主输出与只读写入失败。

验收：证据来自真实工具执行，不只来自 YAML。

排查与边界：镜像拉取、Docker 权限和挂载路径都可能失败；不要靠增加 root 权限盲目排障。

## 4.8-5 cwd 与 Profile

前提：创建无敏感文件的两个练习目录。

参考步骤：分别从 A/B 目录启动同一 Profile，让 terminal 报实际 cwd；再在 Gateway/Cron 流程中验证 terminal.cwd 或任务 workdir。比较 Profile 路径未变而项目路径变化。

验收：解释 Profile 管理配置和状态，cwd 是进程工作位置；CLI 通常使用启动目录。

排查与边界：cwd 不是沙箱；不能宣称 Agent 因 cwd 设置就无法访问其他目录。

依据：[本章官方参考](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)。具体命令以已安装版本帮助为准；题干需修改处另见 [书稿勘误](../docs/book-errata-2026-09-18.md)。
