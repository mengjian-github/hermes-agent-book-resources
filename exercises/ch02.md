# 第2章：环境与复现

对应书稿 2.8，共 3 题。题干为摘要；按书中原顺序编号。核查日期：2026-09-18。共同前提与验证记录见 [练习说明](README.md)。

## 2.8-1 踩坑笔记

前提：使用自己的真实安装记录，不伪造成功输出。

参考步骤：按“平台/版本→命令→错误原文→诊断→修复→复验”记录。示范：在错误目录启动，找不到练习文件；先显示工作目录，再切到仓库根并检查文件存在，重试同一任务。错误日志删去密钥。

验收：另一个读者能根据记录识别原因并复验；记录至少一个曾失败和修复后的对照。

排查与边界：仅写“重装好了”没有可复用证据；未解决的问题明确标未解决。

## 2.8-2 替换为真实任务

前提：选一个可公开或脱敏的小任务，例如归纳自己项目 README。

参考步骤：输入改为“只读本项目 README，给三点目标和缺失信息，不联网、不改文件”；确认启动目录、读取权限、模型已配置及工具能读取。与示例对比所需文件、输出格式和是否联网。

验收：输出对应真实 README，并列出模型、Profile、路径、工具差异。

排查与边界：不要把含密钥的整个工作目录交给模型；路径变化不意味着 Profile 自动切换。

## 2.8-3 最小复现

前提：安装 Hermes、可用模型；依赖和账号问题单独记录。

参考步骤：运行 `hermes --version`、`hermes doctor`，再 `hermes chat --oneshot -q "只回复：环境检查完成"`。保存命令、退出码、最终输出、操作系统、提供商/模型名称；不要记录 Key。

验收：一次性命令完成并退出；doctor 仅辅助诊断，实际回答证明模型调用链。

排查与边界：网络/认证失败不能写成复现成功；报告错误阶段，不复制凭据。

依据：[本章官方参考](https://hermes-agent.nousresearch.com/docs/getting-started/installation)。具体命令以已安装版本帮助为准；题干需修改处另见 [书稿勘误](../docs/book-errata-2026-09-18.md)。
