# 章节练习参考答案

这些答案不是唯一标准。更重要的是读者能说明自己的输入、工具调用过程、输出结果和复盘结论。

## 第 1 章 认识 Hermes

练习目标：区分 Chatbot、Copilot 和 Agent，并说明 Hermes 适合的任务边界。

参考完成标准：
- 能用一个真实任务说明 Chatbot 只回答、Copilot 辅助当前操作、Agent 持续推进目标的差异。
- 能解释 Hermes 与 OpenClaw 的不同定位：OpenClaw 更偏多渠道消息入口和自托管助理，Hermes 更偏 CLI/TUI、工具、Skills、记忆和工程化工作站。
- 能写出 2 个适合 Hermes 的场景，例如仓库审查、资料整理、自动化日报、Telegram 助理。

常见问题：
- 不要把所有 AI 工具都称为 Agent。是否能围绕目标规划、调用工具并根据结果修正，是更关键的判断标准。

## 第 2 章 快速上手

练习目标：完成安装、模型配置和首次可验证任务。

参考完成标准：
- `hermes doctor` 或同类诊断命令能说明配置、模型和终端后端是否可用。
- 能说清 `~/.hermes/config.yaml` 和 `.env` 的分工。
- 首次任务应短小可验证，例如列出当前目录、阅读 README、总结一个小项目用途。

常见问题：
- 网络、证书、代理和模型额度问题通常先于 Hermes 本身出现。排错时先验证外部依赖，再看 Hermes 配置。

## 第 3 章 CLI/TUI 深度使用

练习目标：掌握会话管理、状态查看、多行输入和恢复。

参考完成标准：
- 能创建、命名、恢复一次会话，并说明 `/status`、`/history`、`/compress` 的用途。
- 能写一段多行结构化提示词，让 Hermes 审查一个本地项目的最近改动。
- 能说明什么时候排队、什么时候转向、什么时候中断。

常见问题：
- 长会话不是越长越好。阶段性压缩和命名会话能提高后续恢复质量。

## 第 4 章 配置体系

练习目标：建立适合不同项目的 Profile，并理解配置边界。

参考完成标准：
- 能创建一个 `work` Profile，并说明它隔离哪些状态，不隔离哪些系统权限。
- 能把密钥放进环境变量或 `.env`，而不是写入公开配置。
- 能根据任务风险选择 local、Docker 或 SSH 后端。

常见问题：
- Profile 不是安全沙箱。需要权限隔离时，应结合 Docker、SSH、云沙箱或只读挂载。

## 第 5 章 工具系统

练习目标：根据任务选择最小必要工具。

参考完成标准：
- 能区分只读调研、文件审查、代码修改、浏览器操作所需工具。
- 能让 Hermes 先读事实，再修改，再验证。
- 能用 `git diff` 或测试命令确认修改结果。

常见问题：
- 不要为了安全一次关闭全部工具。更好的做法是按任务开放最小工具集，并在关键节点验证。

## 第 6 章 Skills

练习目标：把一段可复用流程沉淀成 Skill。

参考完成标准：
- `SKILL.md` 包含适用场景、工作流、输入输出格式和验证方式。
- description 能帮助 Agent 判断何时使用该 Skill。
- 至少提供一个成功样例和一个失败处理建议。

常见问题：
- Skill 适合流程复用，不适合替代外部 API 集成。需要新工具能力时，应考虑 Tool、MCP 或 Plugin。

## 第 7 章 记忆与上下文

练习目标：区分会话记忆、持久记忆和可检索历史。

参考完成标准：
- 能把稳定偏好写入用户记忆，把项目规则写入 AGENTS.md 或同类上下文文件。
- 能说明哪些信息适合长期记忆，哪些只适合留在当前会话。
- 能在新会话中恢复一个项目背景，并让 Hermes 正确继续任务。

常见问题：
- 记忆不是越多越好。长期记忆应少量、稳定、可复用。

## 第 8 章 自动化任务

练习目标：创建一个可手动验证再定时运行的任务。

参考完成标准：
- 能写出任务名称、触发规则、工作目录、提示词和投递方式。
- 首次创建后先手动运行一次，确认输出质量。
- 失败时能定位是脚本、环境变量、Gateway、模型还是投递渠道的问题。

常见问题：
- 定时任务提示词要具体，避免让 Agent 每天重新猜测输出结构。

## 第 9 章 多 Agent 协作

练习目标：判断什么时候需要委派、并行或 Kanban。

参考完成标准：
- 能把一个复杂任务拆成互不冲突的子任务。
- 能为子 Agent 写清 goal、context、toolsets 和交付格式。
- 能说明 delegate_task、Kanban、Cron、Webhook 的适用差异。

常见问题：
- 不要为了“看起来智能”而过度委派。简单文件读取和确定性脚本应直接完成。

## 第 10 章 Telegram 与消息平台

练习目标：把 Hermes 接入消息入口，并设置权限边界。

参考完成标准：
- Bot Token 放在环境变量或 Secret 中。
- 配置 allowed users 或等价白名单。
- 能说明 polling 与 webhook 的取舍。

常见问题：
- 多实例部署时，每个 Bot Token 同一时间只应由一个 Gateway 实例使用。

## 第 11 章 生产部署

练习目标：把一个 Hermes 实例放入可维护、可恢复的运行环境。

参考完成标准：
- 有独立运行用户、日志目录、环境变量管理和重启策略。
- 有最小权限的 SSH 密钥或部署凭证。
- 有故障恢复步骤，包括服务重启、日志定位、配置回滚和密钥轮换。

常见问题：
- 生产环境关注的不只是能否启动，还包括谁能访问、能在哪里执行命令、出错后如何恢复。

## 第 12 章 MCP 与生态扩展

练习目标：接入一个低风险、只读优先的外部工具或知识源。

参考完成标准：
- 能说明 MCP server 提供哪些工具，哪些工具只读，哪些工具禁止写入。
- 能完成一次真实查询，并记录输入、输出和权限边界。
- 能说明如何回滚或禁用该 MCP 配置。

常见问题：
- 不要先追求接入数量。权限边界、工具过滤和可回滚设计比“能连上”更重要。
